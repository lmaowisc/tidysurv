# Editing Tidy Survival Analysis in RStudio

This folder is a self-contained native Quarto website project. The `.qmd` files are the editable manuscripts. The website is edited directly in the main course folder. The original slide sources (`sec1.qmd` through `sec5.qmd`) and data remain in place. A snapshot of the files replaced during the redesign is saved in `course-before-redesign.zip`.

## Open and preview

1. Open `tidysurv.Rproj` in RStudio.
2. Open `index.qmd` or a chapter file such as `intro.qmd`. Source mode is recommended; prose uses ordinary Markdown.
3. In RStudio's Terminal tab run `quarto preview --port 8262`. Open `http://localhost:8262/` if it does not open automatically. Saving an edited chapter rebuilds its preview.
4. To build the entire site, run `quarto render` from that same terminal, or use RStudio's Render Website button in the Build pane.

The website is written to `_site/`. Never edit that generated folder. Previewing and rendering do not publish anything.

Quarto retains intermediate Markdown and figure folders to avoid moving those folders while Dropbox is syncing them. These generated files are ignored by Git; continue editing the `.qmd` manuscripts.

## Writing chapters

Write paragraphs separated by blank lines. Use `##` for sections, `###` for subsections, `$...$` for inline equations, and `$$` on separate lines for displayed equations. These headings automatically populate the contents rail. Use ordinary Markdown image links, for example `![Follow-up plot](images/rat_swim.png)`.

Chapters 1 and 2 use automatic section numbering. Main sections (`##`) appear as 1.1, 1.2, or 2.1, 2.2; subsections (`###`) add a third number. Their front matter sets `number-sections`, `number-depth`, a chapter-specific `number-offset`, and `crossref: chapters: true`. Keep numbers out of the heading text so that reordering sections renumbers them automatically. Exercise titles and further-reading headings use `{.unnumbered}`. Preserve explicit heading IDs when renaming headings so that existing links continue to work.

R code goes in executable chunks:

````markdown
```{r}
#| label: my-survival-fit
library(survival)
gbc_mort <- read.table("data/gbc_mort.txt", header = TRUE)
survfit(Surv(time, status) ~ 1, data = gbc_mort)
```
````

For a code example that should be displayed without running, add `#| eval: false`. For a collapsed solution, add `#| code-fold: true` and `#| code-summary: "Solution"`.

The first two chapters execute their examples and exercise solutions when rendered. Chunk options such as `#| eval: false` belong inside executable R chunks and are processed by Quarto, not shown as reader code. Later chapters retain the supplied non-executing code collections. `freeze: auto` avoids rerunning unchanged chapters during full builds. After changing data or installed packages, explicitly render the affected chapter (for example `quarto render intro.qmd`) to refresh its results.

The later chapters and resources page currently have `execute: enabled: false` in their front matter, because they only display code. When adding executable examples there, remove that setting and change the relevant chunk's `eval` option to `true`.

The project requires Quarto, R, `knitr`, `rmarkdown`, `survival`, `tidyverse`, `gtsummary`, `ggsurvfit`, `broom.helpers`, and `gt` for the executable examples. Reader package instructions are in `resources.qmd`. The optional export examples create files under `outputs/` when run manually; they do not run while rendering. No separate website framework is needed.

## Rebuild the cover figure

Run `Rscript code/make-cover.R` from this project folder (or source that file in RStudio). It fits Kaplan–Meier estimates to the supplied GBC data and saves `images/cover-survival.svg`.

The front-page Cox table is generated by the `cover-cox-table` R chunk in `index.qmd`. It uses the illustrative model from Chapter 1 and displays selected adjusted estimates. Edit its labels and accompanying text in that file; `quarto render index.qmd` refreshes the estimates. If Chapter 1's model changes, update the matching formula here too.

## Prototype scope

The design includes a course overview, five chapter pages, search, chapter navigation, section contents, copyable code, and downloads. Chapters 1 and 2 have expanded narrative, worked examples, interpretation, and exercises; their downloadable scripts follow the chapter chunks in order. Chapters 3–5 carry under-construction notices and retain slides and code pending narrative expansion and review. Official package documentation supplements the original slides; extensions should include sources, executable examples, argument explanations, and interpretation appropriate to each chapter.

## Publish updates

The public address is https://lmaowisc.github.io/tidysurv/. Push reviewed source changes to `master`. The `Build and publish book` GitHub Actions workflow installs R dependencies, executes the examples with Quarto, checks local links and downloads, and deploys `_site/` to GitHub Pages. Its `ci` profile disables frozen output so that each deployment is built from the current source. Check the Actions result before assuming an update is public.

The old `docs/` directory is a historical generated site and is no longer the deployment source. Do not edit or stage it for new updates. The local backup ZIP and optional `outputs/` exports are not publication inputs. Edit `.qmd` files in RStudio and update the corresponding downloadable scripts when code changes.
